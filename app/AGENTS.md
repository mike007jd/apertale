# Prototype Instructions

Run the local server yourself and open the preview in the browser available to this environment. Do not give the user server-start instructions when you can run it.

Before making substantial visual changes, use the Product Design plugin's `get-context` skill when the visual source is unclear or no longer matches the current goal. When the user gives durable prototype-specific design feedback, preferences, or decisions, record them in `AGENTS.md`.

When implementing from a selected generated mock, treat that image as the source of truth for layout, component anatomy, density, spacing, color, typography, visible content, and hierarchy.

Build app UI in `src/`. Keep `.openai/hosting.json`, `worker/index.js`, `scripts/prepare-sites-build.mjs`, and `tests/sites-worker.test.mjs` intact so the same local prototype can be handed to Sites. Before a Sites handoff, run `npm run test:sites` (it performs the production build first, so no separate `npm run build` is needed) and verify that the build leaves `dist/client/app-shell`, `dist/server/index.js`, `dist/.openai/hosting.json`, and the numbered migrations under `dist/.openai/drizzle/`.

## Apertale product decisions

- Use `../docs/assets/livingbook-day-theme-reference.png` as the primary editing-layout truth and `livingbook-night-theme-reference.png` as the same product in its cinematic night presentation preset.
- The bottom `Create Your Own` action opens a full-screen blank-book workshop; it is a visible Agent/WebMCP handoff, not a form modal or second embedded AI composer.
- Before final artwork, let Codex draw the complete rough storyboard directly on that blank 3D book with `sketch_storyboard`. Readers only add small red freehand corrections on the real page surface; Codex ends the sketch turn for reader review. After approval it reuses the agreed plan; when new red marks are reported, it reads them once, revises only affected spreads, clears applied marks, and continues without another confirmation. Keep one pencil style and one annotation mode rather than a general drawing editor.
- Enter and leave the `Create Your Own` workshop through one reversible, origin-aware paper transition: expand from the actual CTA, change the mounted scene only while the paper covers the viewport, and reveal the source back toward that CTA on exit. Lock repeated input during the handoff, preserve focus return, and use an immediate state handoff under Reduced Motion.
- Keep day and night as presentation state outside the document revision. Document mutations use the shared command engine and remain undoable across human and WebMCP actions.
- Render the book as a real WebGL scene with deforming page geometry, while preserving the 2D fallback and reduced-motion path.
- Treat the earlier city/bird and fox spreads as baseline technical fixtures, not the quality target. The primary showcase is a premium illustrated knowledge book with full-spread OpenAI ImageGen artwork, layered interactions, and short frame sequences.
- Every showcase element has declarative, Agent-authored hover and click behavior. Validate behavior against closed presets; never execute model-authored JavaScript, GLSL, or arbitrary URLs.
- Use real generated/source assets and Phosphor icons; do not replace production art with CSS drawings, emoji, text glyphs, gradients, or placeholder imagery.
- Users bring their own ChatGPT/Codex conversation and model usage. Do not add an owner-funded OpenAI API key or a fake in-page AI composer.
- Story requests and source photos begin in the user's Agent conversation. Prefer verified host media transfer; while WebMCP attachment transfer remains non-standard, expose one quiet **Image handoff** fallback that creates stable local `assetId` values without asking the user to repeat the brief.
- Make `request_image_handoff` return as soon as its drawer and drop target are visible. Let the calling Agent inspect its own tool inventory: use Computer Use or a browser file chooser when available; otherwise open the actual local asset folder and ask the reader to drag its files into the page once. Keep host capability detection with the Agent, because the page cannot inspect the Agent's tools.
- Make the first-run experience a clean editorial library of separate hardcovers laid directly on the page; do not introduce a literal furniture-style shelf. Put the built-in Guide Book first, keep every sample as an independent book, and make `Create Your Own` the unmistakable primary authoring path from both library and reader.
- Keep the fallback image handoff inside the creation workshop and visually secondary to the Agent path. Finished-book controls must not expose a context-free `Add` action.
- Give every book a dedicated generated portrait cover; never reuse an interior spread, thumbnail crop, flat color block, or CSS-drawn stand-in as cover art.
- Never style a copy action like an editable prompt field. The creation CTA opens the full-screen blank-book workshop and points to the Codex/ChatGPT conversation beside the built-in browser; copying a starter prompt is an explicit secondary action.
- After a starter prompt is copied, keep a smaller re-copy action beside an honest Codex handoff status. Treat Site Tools registration as readiness, not attachment; only say Codex found the page after a real tool call.
- Explain three supported authoring paths concisely: text-to-book with model-authored copy and ImageGen artwork, photo-led books with an explicit image import handoff, and illustration-led books with layered interactions or short frame sequences.
- Label built-in scenes honestly and quietly: `Curated samples use OpenAI-generated illustration. Create your own with Codex and ImageGen in your active conversation.` Do not imply the checked-in sample assets were generated live in the viewer.
- Keep content generation inside the OpenAI/Codex ecosystem. The runtime ships no content 3D models or external model-generation pipeline; Three.js is reserved for the physical book, page turn, lighting, particles, and raycasting.
- Opening a book must acknowledge the click immediately and keep an honest loading state visible until the first complete book frame is ready. Reduced motion preserves status text without sustained rotation.
- During a cold open, keep the selected cover at normal contrast while navigation is locked. If the reader stage must appear before its first complete frame, show a neutral book-frame skeleton and withhold unavailable reader controls. Retain the ready current reader scene across Books closes so reopening it stays warm, while the initial shelf remains cold until intent.
- Keep the public deployment private until the user explicitly approves a new release. Do not expose Challenge wording in customer-facing product UI or branding.
- Preserve a sparse, full-screen editing surface: the book remains the dominant object, controls float at the edges, and Story Outline stays secondary.
- Present Night across the complete library and reader as a dark room with light typography, controls, and shelf details; keep full-screen dialog sheets transparent so the room remains visible. Use a local warm desk-lamp pool that keeps the entire open book readable without a uniform wash over the artwork.
- Separate time-based effects from their clean base illustration. Keep the base readable at rest, use brief authored frame bursts, and hold the rest frame under Reduced Motion.
- Give every shipped spread at least one meaningful declarative motion/hover/click element; use lightweight procedural markers for knowledge details instead of adding runtime content models.
- Keep illustrated foreground layers still by default. Signal clickability with a restrained hover rim, light, or short lift; only assign idle translation when the subject semantics and page bounds support it. Boats on water use a small local bob and never travel onto land, while people, buildings, monuments, and resting props remain still until hover or focus.
- Ground every building, monument, person, tree, and resting prop on a visible surface in the final rendered spread. Align the cutout's lowest opaque contact edge with the matching architecture, terrain, floor, waterline, or shadow in the clean plate; keep its scale and perspective consistent with that surface. Before release, inspect every built-in spread at a settled frame and while its interactive layers are selected, and adjust or reject any layer that floats, duplicates the baked subject, crosses the gutter/page edge unintentionally, or exposes a selection bound materially larger than the visible subject.
- Treat mobile as a first-class authored composition, not a scaled desktop fallback. Every primary control must acknowledge touch immediately; Day/Night must visibly select on tap and settle the complete room, lamp, book, and artwork presentation within roughly 300ms on a healthy device.
- On phone-sized portrait readers, show a visual-first animated rotate-to-landscape gate so the physical spread remains dominant. Animate the phone itself without a decorative badge or redundant direction arrow. Let rotation dismiss it automatically, honor reduced motion, and retain a quiet `Stay portrait` escape for rotation lock and accessibility needs.
- In portrait mobile readers, present a complete single-page binding instead of cropping one side of the open spread. Keep the binding centered with its spine, board, paper block, and shadow visible; place the authored right page into it by default, and swap the existing left-page mesh into the same shell when a left-page element is selected. Never leak the opposite page or board. Keep the original full spread in landscape, preserve exact half-spread UV sampling in WebGL and the 2D fallback, and let Story own the full reflowed copy.
- Build every new image-led spread from the original composite, its clean background plate, and the foreground count selected by creationBrief.interactionDensity. Let the existing import/create path validate real alpha and asset roles; use the live authoring guide for minimum completion checks and reserve full visual polish for a reader request.
- Follow get_project_context(detail: "authoring-guide") for the approved-sketch generation and handoff sequence. Generate interiors and cutouts in 2×2 sheets; cutout subjects use a flat magenta backdrop and become separate real-alpha assets through the existing split/key import. Retain successful assets and replace only confirmed failures. The live guide is the execution source of truth; the authoring skill references explain tool usage and art direction.
- Treat the selected cover and the open book as one persistent object rendered inside one opaque, theme-aware transition stage. Opening moves the chosen cover to the reading stage, hands off to the real current spread from the gutter, and never exposes a mirrored cover back or blank proxy page; returning to Books reverses that path and lands the closed cover in its own library position. Keep the old reader, library, and controls visually isolated during the handoff, keep loading honest before it, lock competing navigation while it runs, restore focus at settle, and replace the spatial sequence with an immediate state change under Reduced Motion.
- Bind the resolved cover image to the hardcover geometry's real outer face, not a coplanar proxy plane, and carry the same image on the front-matter face that sits in front of it during the opening arc. Keep the printed case continuous through every closed, edge-on, opening, and closing pose, and do not start the handoff until the selected cover has either resolved or reached an explicit fallback.
- Give every personal book in `Your books` a directly visible delete action with destructive confirmation. Serialize deletion with the existing library and publication lifecycle locks; curated books cannot be deleted, and a personal book with publication state must remove that publication before its local copy can disappear.
- Give the whole-book library handoff its own motion duration, separate from page navigation. During a Night opening, let the library fall dark before raising the real desk lamp with the opening case. Preserve readable closed, travelling, half-open, and settled poses in both directions; keep the reverse path spatially faithful and settle immediately under Reduced Motion.
- Keep the server-delivered first paint visible until the selected application chunk mounts. Use an honest editorial-library skeleton with neutral blocks, no fake book artwork or flat open spread, and freeze its pulse under Reduced Motion.
- Use soft paper-on-desk shadows on both library covers and the WebGL book. Build a broad penumbra without hard offset slabs, and keep shadow softness within the existing shadow-map budget.
